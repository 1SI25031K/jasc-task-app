# JASC タスクマネージャー 要件定義書 v1.3

最終更新：2026-11-03
- v1.2：Slack 通知・英語 UI・進捗グラフ・議事メモからの NA 生成を追加
- v1.3：負荷の見える化（自動負荷・体感負荷・余力マップ）、依頼と承諾の流れ、個人 DM リマインド、週次の完了まとめを追加

対象：第79回日米学生会議 日本側実行委員会

---

## 1. 目的と解決したい課題

| 課題 | このアプリでの解決策 |
|---|---|
| 誰がどんな作業をしているか見えず、**任せて良いか判断できない** | タスクと NA を役職ごとに表示する／**自動負荷と体感負荷**を全員が見られる「余力マップ」／担当者を選ぶときに負荷を表示する |
| 見えないことで、**不要な不満**が生まれる | **依頼と承諾の流れ**（勝手に振らない）／毎週の「先週の完了」まとめで貢献を見えるようにする |
| **リマインドの手間** | Slack の**個人 DM で自動リマインド**（期限前日・当日・超過・停滞・依頼の未返答・体感負荷の入力） |
| 定例会で決まったことが放置される | 議事メモから NA 候補を作り、その場で登録する |

あわせて、来年度の実行委員にも引き継げる、シンプルで壊れにくい仕組みにする。

## 2. 利用者と権限

| 項目 | 内容 |
|---|---|
| 利用者 | 日本側実行委員（約8名）。米国側実行委員の参加時は英語 UI で利用 |
| ログイン | Google アカウントでログイン。**メンバー名簿に登録されたメールアドレスのみ** 利用可 |
| 閲覧・編集 | ログインできる全員が、全タスクを閲覧・作成・編集できる |
| 負荷の閲覧 | **全員が全員の自動負荷・体感負荷を閲覧できる** |
| 管理者 | メンバー・役職・設定のマスタ管理は、管理者がスプレッドシートを直接編集して行う（アプリに管理画面は作らない） |
| 画面言語 | 日本語／英語（ユーザーごとに切替。既定は日本語） |

## 3. 技術構成

| 要素 | 採用 |
|---|---|
| 言語 | Python 3.12 |
| UI フレームワーク | Streamlit（最新安定版。`st.login` / `st.navigation` を使用） |
| データ保存 | Google スプレッドシート（`gspread` + サービスアカウント） |
| 認証 | Google OIDC（Streamlit の `st.login("google")`） |
| グラフ | Streamlit 標準のグラフ機能。不足時のみ Altair |
| 定時処理 | GitHub Actions のスケジュール実行（cron）で Python スクリプトを実行 |
| Slack | **Slack アプリの Bot トークン**（`chat:write` 権限）で、チャンネル投稿と個人 DM を送る。`slack_sdk` を使用 |
| AI（議事メモ → NA） | Gemini API（Google AI Studio で API キーを発行、`google-genai` SDK）。モデル名は設定で指定 |
| ホスティング | Streamlit Community Cloud（無料） |
| ソース管理 | GitHub（**private リポジトリ**） |
| パッケージ管理 | `uv`（`pyproject.toml` と lock ファイルでバージョン固定） |
| テスト | `pytest` |
| 開発環境 | macOS + Google Antigravity |

### 設計方針
- **データアクセス層を抽象化する**（`Repository` インターフェース）。実装は「インメモリ（テスト・ローカル開発用）」と「Google スプレッドシート」。
- **外部サービスも抽象化する**（`Notifier` / `NaExtractor`）。テストではダミー実装を使い、実際に通信しない。
- 画面（pages）にはビジネスロジックを書かない。期限判定・負荷計算・リマインド対象の抽出・通知文の組み立て・AI 出力の検証は `core/` に置き、テストする。
- 画面の文言は翻訳ファイル（`locales/ja.toml` / `locales/en.toml`）から読む。フェーズ2の画面作成時点からこの仕組みで作る。
- 曜日・時刻・しきい値などの運用パラメータは `settings` シートに置き、コードを変えずに調整できるようにする。
- アプリが止まっても、実行委員がスプレッドシートを直接見て運用を継続できるデータ構造にする。

## 4. データ設計（スプレッドシートのシート構成）

### 4.1 `members`（メンバー）
| 列 | 型 | 説明 |
|---|---|---|
| member_id | 文字列 | 例：`m001` |
| display_name | 文字列 | 表示名（姓のみ等） |
| display_name_en | 文字列 | 英語表示名。空なら display_name を使う |
| email | 文字列 | ログイン照合用。小文字で比較する |
| main_roles | 文字列 | 主役職の role_id をカンマ区切り |
| lang | 文字列 | `ja` / `en` |
| slack_user_id | 文字列 | **DM の送り先**（例：`U0123ABCD`）。空の人には DM を送らず、管理者向けの一覧に「未設定」と出す |
| reminders_enabled | TRUE/FALSE | 個人 DM リマインドを受け取るか（既定：TRUE） |
| is_admin | TRUE/FALSE | 管理者フラグ |
| active | TRUE/FALSE | FALSE の人はログイン不可・通知対象外 |
| bg_mode | 文字列 | 背景モード（`standard` / `color` / `bing`。既定：`standard`） |
| bg_color | 文字列 | 背景色識別子（`standard` / `blue` / `teal` / `green` / `yellow` / `orange` / `pink` / `purple` / `gray`。既定：`standard`） |

### 4.2 `roles`（役職）
| 列 | 型 | 説明 |
|---|---|---|
| role_id | 文字列 | 例：`r_selection` |
| name / name_en | 文字列 | 表示名（日本語／英語） |
| category | 文字列 | `主役職` / `副役職` / `サイト` / `その他` |
| sort_order | 数値 | 表示順 |
| active | TRUE/FALSE | FALSE は非表示 |

初期データ（暫定。管理者が随時追加・変更する）：

- **主役職**：実行委員長、副実行委員長、財務、広報、選考
- **副役職**：春合宿、安全保障研修、自主研修、直前合宿、リスクマネジメント、JASC COMEBACK、業務効率化、定例会、報告書、関西業務、報告会、福島研修
- **サイト**：東京サイト、関西サイト、岩手サイト
- **その他**：CVC（※正式名称・区分は要確認）

※「関西業務」（副役職）と「関西サイト」（サイト）は別の役職。
※英語名の初期値はエージェントが案を作り、管理者が確認する。
※担当者の割り当ては実在の氏名を含むため、リポジトリには書かず、管理者がスプレッドシートに直接登録する。

### 4.3 `role_assignments`（役職の担当割り当て）
| 列 | 型 | 説明 |
|---|---|---|
| role_id | 文字列 | |
| member_id | 文字列 | |
| kind | 文字列 | `責任者` / `担当` / `サポート` |

- 1役職につき `責任者` は1名。名簿の括弧書きは `サポート` として扱う。

### 4.4 `tasks`（タスク）
| 列 | 型 | 必須 | 説明 |
|---|---|---|---|
| task_id | 文字列(UUID) | ○ | 自動採番 |
| title | 文字列 | ○ | タスク名 |
| role_ids | 文字列 | ○ | 関係する役職の role_id をカンマ区切り。**複数可** |
| owner_member_id | 文字列 | ○ | 担当者（**1名**） |
| requested_by | 文字列 | | 依頼した人の member_id（自分で自分に作ったタスクは空） |
| assignment_status | 文字列 | ○ | `承諾済` / `依頼中` / `相談中`（5.3 参照） |
| assignment_comment | 文字列 | | 「相談したい」を選んだときのコメント |
| weight | 文字列 | ○ | **重さ**：`軽` / `中` / `重`（既定：中）。目安は 5.4 |
| next_action | 文字列 | ○ | NA。すぐ動ける粒度の1行 |
| na_due | 日付 | ○ | NA の期限 |
| task_due | 日付 | | タスク全体の期限（任意） |
| status | 文字列 | ○ | `未着手` / `進行中` / `待ち` / `完了` |
| waiting_on_member_id | 文字列 | | status=待ち のとき、待っている相手（メンバーの場合）。リマインド対象になる |
| priority | 文字列 | | `高` / `中` / `低`（既定：中） |
| blocker | 文字列 | | 止まっている理由・依頼先（メンバー以外の場合はここに書く） |
| notes | 文字列 | | メモ（個人情報を書かない旨を入力欄に表示） |
| source | 文字列 | ○ | `manual` / `minutes` |
| meeting_id | 文字列 | | 議事メモから生成した場合の会議 ID |
| completed_at / completed_by | 日時 / member_id | | 完了にした日時・人（進捗グラフと週次まとめに使う） |
| created_at / created_by | 日時 / member_id | ○ | 自動 |
| updated_at / updated_by | 日時 / member_id | ○ | 自動 |
| archived | TRUE/FALSE | ○ | 削除の代わり |

### 4.5 `checkins`（体感負荷）
| 列 | 説明 |
|---|---|
| checkin_id | 自動採番 |
| member_id | 回答した人 |
| date | 回答日（Asia/Tokyo） |
| score | 体感負荷 1〜10（1＝かなり余裕がある、10＝限界） |
| comment | 任意の一言（例：「来週テスト」「岩手の調整が山場」）。最大100文字 |
| auto_load_at_checkin | 回答時点の自動負荷（後から振り返るため） |

- 同じ人が同じ日に2回答えた場合は、新しい回答で上書きする。
- 入力欄に「**体調などの詳しい理由は書かなくて大丈夫です**（全員が閲覧できます）」と表示する。

### 4.6 `activity_log`（変更履歴）
| 列 | 説明 |
|---|---|
| timestamp | 日時（Asia/Tokyo） |
| member_id | 操作した人（定時処理は `system`） |
| task_id | 対象タスク |
| action | `create` / `create_from_minutes` / `update` / `request` / `accept` / `consult` / `archive` / `restore` |
| field / old_value / new_value | 変更内容（update 時） |

### 4.7 `meetings`（議事メモから NA を生成した会議）
| 列 | 説明 |
|---|---|
| meeting_id / meeting_date / title | 会議の情報 |
| created_by / created_at | 実行した人・日時 |
| generated_count / saved_count | AI が出した候補数／実際に登録した数 |

※議事メモの本文は保存しない。

### 4.8 `daily_snapshots`（進捗グラフ用の日次集計）
| 列 | 説明 |
|---|---|
| date | 集計日 |
| scope_type | `ALL` / `role` / `member` |
| scope_id | role_id または member_id（ALL のときは空） |
| total / done / open / overdue | タスク総数／完了数／未完了数／期限切れ NA 数（アーカイブ除く） |
| completion_rate | done / total |
| auto_load | 自動負荷（scope_type=member のとき） |

- 同じ日付・同じ対象の行がすでにあれば上書きし、重複させない。

### 4.9 `reminder_log`（送信済みリマインド）
| 列 | 説明 |
|---|---|
| sent_at | 送信日時 |
| member_id | 送り先 |
| kind | `due_tomorrow` / `due_today` / `overdue` / `overdue_escalation` / `waiting` / `stale` / `request_pending` / `checkin` / `high_load_alert` |
| task_id | 対象タスク（checkin・high_load_alert は空） |
| date_key | 送信日（YYYY-MM-DD） |

- **同じ（member_id, kind, task_id, date_key）の組み合わせは1日1回しか送らない**。定時処理を再実行しても二重送信しないため。

### 4.10 `settings`（運用パラメータ）
| key | 初期値 | 説明 |
|---|---|---|
| checkin_weekdays | `月,水,金` | 体感負荷を聞く曜日（週3回） |

| load_window_days | `14` | 自動負荷の計算に含める期間（日） |
| weight_points | `軽=1,中=2,重=3` | 重さのポイント |
| overdue_escalation_days | `3` | 超過何日で役職責任者にも知らせるか |
| stale_days | `7` | 停滞とみなす日数 |
| request_reminder_days | `2` | 依頼に返事がないとき何日後にリマインドするか |
| high_load_score | `8` | 体感負荷アラートのしきい値 |
| high_load_consecutive | `2` | しきい値以上が何回続いたらアラートを出すか |
| summary_channel_id | （空） | 毎朝のまとめ・週次まとめを投稿するチャンネル |
| app_url | （空） | 通知に載せるアプリの URL |
| feature_ai_search | `FALSE` | ホーム画面の AI 問い合わせ機能の有効化フラグ（TRUE/FALSE。本番課金有効化前は FALSE で安全にデプロイ可能） |
| rate_limit_ai_search_per_minute | `5` | 1メンバーあたりの1分間 AI 検索呼び出し上限回数 |
| rate_limit_ai_search_per_day | `50` | 1メンバーあたりの1日（24時間） AI 検索呼び出し上限回数 |
| drive_ai_shared_folder_id | （空） | Google Drive の「AI共有」フォルダID |
| gemini_file_search_store_name | （空） | Gemini File Search Store のリソース名（自動管理） |
| feature_drive_file_search | `FALSE` | Google Drive 資料連携（File Search）の有効化フラグ（TRUE/FALSE） |

### 4.11 `ai_queries`（AI 問い合わせ履歴）
ホーム画面の検索バーからの AI 問い合わせ実行ログを記録するシート（全7列）。監査および機能改善のために利用する。
**個人情報保護のため、AI が生成した回答本文は本シートには保存しない（S12）**。

| 列名 | 型 | 説明 | 例 |
|---|---|---|---|
| query_id | 文字列 | 問い合わせの一意識別子（UUID または `Q-タイムスタンプ`） | `Q-1731139200-abcd` |
| timestamp | 日時 | 問い合わせ実行日時（ISO 8601） | `2026-11-09T16:00:00Z` |
| member_id | 文字列 | 質問者のメンバーID | `M001` |
| query_text | 文字列 | 質問文（メールアドレス・電話番号マスキング後） | `今週期限のタスクは何ですか？` |
| grounded_task_ids | 文字列 | 回答内で引用されたタスクID（カンマ区切り） | `T-001,T-004` |
| status | 文字列 | 実行ステータス（`SUCCESS` / `RATE_LIMITED` / `ERROR` / `DISABLED`） | `SUCCESS` |
| error_message | 文字列 | エラー時の内容（成功時は空） | `QuotaExceeded` |

### 4.12 `drive_sync_logs`（Google Drive 資料同期ログ）
Google Drive 専用フォルダ「AI共有」から Gemini File Search Store へ同期された資料の履歴・状態を管理するシート（全9列）。

| 列名 | 型 | 説明 | 例 |
|---|---|---|---|
| file_id | 文字列 | Google Drive のファイル一意ID | `1A2b3C4d5E...` |
| file_name | 文字列 | ファイル名 | `2026サマーフォーラム企画書.pdf` |
| mime_type | 文字列 | ドキュメントの MIME タイプ | `application/pdf` |
| drive_modified_time | 日時 | Drive 側での最終更新日時（ISO 8601） | `2026-11-08T15:30:00Z` |
| gemini_file_resource_name | 文字列 | Gemini File Search Store 内の登録リソース名 | `files/abcdef12345` |
| status | 文字列 | 同期ステータス（`INDEXED` / `SKIPPED_PII` / `ERROR` / `REMOVED`） | `INDEXED` |
| drive_link | 文字列 | ドキュメント閲覧用リンク（URL） | `https://drive.google.com/file/d/.../view` |
| last_synced_at | 日時 | 同期実行日時（ISO 8601） | `2026-11-09T08:00:00Z` |
| error_message | 文字列 | スキップ・エラー理由（個人情報検知内容など） | `メールアドレスを検知 (1件)` |

## 5. 機能要件（すべて v1.0 リリース範囲）

### 5.1 基本機能
| # | 画面・機能 | 内容 |
|---|---|---|
| F1 | ログイン | Google ログイン → `members` の active なメールと照合。未登録ならアクセス権がない旨とログアウトボタンだけを表示 |
| F2 | 役職ボード（ホーム） | 全役職をカテゴリ別にカード表示。各カードに：責任者名、未完了タスク数、期限切れ NA 数（赤）、今週期限の NA 数、最も期限の近い NA 1件。ページ上部に「**あなたへの依頼 ○件**」「**体感負荷が未回答です**」のお知らせを表示（該当時のみ） |
| F3 | 役職詳細 | その役職の未完了タスク一覧（NA 期限順）、完了タスク（折りたたみ）、担当メンバー（各人の自動負荷・最新の体感負荷も表示）、完了率グラフ |
| F4 | マイタスク | 自分が担当者のタスク。「依頼中（返事待ち）」「進行中」「待ち」「完了（直近）」に分けて表示。自分の自動負荷・体感負荷も表示 |
| F5 | 期限アラート | ①期限切れ NA ②今週期限の NA ③停滞タスク ④返事のない依頼。定例会で画面共有して使う想定 |
| F6 | 全タスク一覧 | 役職・担当者・ステータス・依頼状態・キーワード・作成元で絞り込み |
| F7 | タスク作成 | 必須項目のバリデーションあり。役職は複数選択。**担当者の選択肢に、各メンバーの自動負荷と最新の体感負荷を表示**（例：「宮本（自動 9pt／体感 7）」）。自分以外を担当者にすると「依頼」になる（5.3） |
| F8 | タスク編集 | 全項目を編集可能。「NA を更新」専用の簡易フォーム（NA・NA期限・ステータス）。担当者を変更した場合も「依頼」になる |
| F9 | アーカイブ／復元 | 物理削除はしない |
| F10 | 変更履歴 | 各タスクの変更履歴を表示 |

### 5.2 追加機能
| # | 機能 | 内容 |
|---|---|---|
| F11 | 英語 UI 切替 | 日本語／English を切替。`members.lang` に保存。画面の文言・役職名・ステータス名・重さ・日付形式を翻訳。ユーザーが入力した本文は翻訳しない |
| F12 | 毎朝のまとめ投稿 | 毎朝、`summary_channel_id` のチャンネルに投稿：期限切れ NA 一覧・今日期限の NA・件数サマリー・アプリへのリンク。0件の日は短い一文だけ |
| F13 | 進捗グラフ | 「進捗」ページ：①全体の完了率の推移 ②役職別の現在の完了率 ③役職別の期限切れ NA 数 ④**メンバー別の自動負荷の推移**。期間（4週／12週／全期間）を選択。推移はリリース日以降のデータから |
| F14 | NA 生成 | 議事メモを貼り付け → Gemini が NA 候補を返す → 人が確認・修正 → チェックした行だけ登録（5.7）。担当者の選択肢には負荷を表示。自分以外を担当者にした行は「依頼」として登録される |
| F15 | **余力マップ** | 全メンバーを一覧で表示：自動負荷（棒グラフ）、最新の体感負荷（1〜10）と一言、体感負荷の直近4回の推移（小さな折れ線）、今週期限の NA 数、返事待ちの依頼の数。**自動負荷と体感負荷のずれが大きい人**（5.4）には印を付ける。ページ上部に「この数字は評価には使いません。分担を話し合うための材料です」と常に表示 |
| F16 | **体感負荷チェックイン** | 1〜10 のボタンを1回押すだけで回答できるページ（任意で一言）。回答すると、自分の自動負荷と、前回の回答も表示する。Slack の DM のリンクからこのページを直接開けるようにする |
| F17 | **依頼の受信箱** | 自分への依頼を一覧表示。各依頼に「承諾」「相談したい（コメント必須）」ボタン。結果は依頼した人に DM で知らせる |
| F18 | **個人 DM リマインド** | 5.6 のルールで、毎朝 Slack の個人 DM を送る |
| F19 | **週次の完了まとめ** | 毎週月曜の朝、チャンネルに投稿：先週完了したタスク（役職ごと・担当者名付き）、全体と役職別の完了数、今週期限の主な NA。完了0件の役職は載せない（責める形にしない） |
| F20 | **ホーム検索バー AI 問い合わせ** | ホーム画面の Search bar から AI に自然言語で質問・タスク検索。AI 回答（上）と関連タスク一覧（下）の 2 層表示。厳格なホワイトリストと PII マスキング、プロンプトインジェクション防御、M3 チップ連携（5.8） |
| F21 | **Google Drive 資料連携（File Search）** | 専用フォルダ「AI共有」の資料を自動索引化。F14（NA生成）および F20（AI問い合わせ）でタスクと資料を横断参照。タスク根拠と資料根拠を画面上で明確に区別し、元資料への閲覧リンクを表示（5.9） |

### 5.3 依頼と承諾の流れ
- 自分を担当者にしてタスクを作成した場合：`assignment_status=承諾済`、`requested_by` は空。
- **自分以外**を担当者にした場合：`assignment_status=依頼中`、`requested_by=作成者`。担当者に DM「○○さんから依頼が届いています」を送る（次の定時処理で）。
- 担当者が「承諾」→ `承諾済`。依頼した人に DM で知らせる。
- 担当者が「相談したい」（コメント必須）→ `相談中`。依頼した人に、コメント付きで DM で知らせる。依頼した人は、担当者を変更する（再び依頼になる）か、内容を調整して再依頼する。
- 依頼中のまま `request_reminder_days` 日が過ぎたら、担当者にリマインドする。
- 依頼中・相談中のタスクも、担当者の自動負荷には含める（「来るかもしれない仕事」も負荷として見える方がよいため）。ただし余力マップでは、承諾済の分と依頼中の分を色分けして表示する。

### 5.4 負荷の計算ルール
- **重さの目安**（入力欄の横に表示する）：
  - `軽`＝1〜2時間で終わる（例：メール1通、日程調整）
  - `中`＝半日〜1日程度（例：資料作成、見積の比較）
  - `重`＝数日以上かかる、または複数人との調整が必要（例：宿泊先の確保、プログラムの設計）
- **自動負荷（pt）**＝ 担当者が自分で、status ≠ 完了、アーカイブされていない、かつ「NA 期限が今日から `load_window_days` 日以内」または「期限切れ」のタスクについて、重さのポイントを合計したもの。
- **体感負荷**＝最新の checkins の score。最後の回答から7日以上経っていたら「未回答」と表示する。
- **ずれの判定**：全メンバーの自動負荷を 1〜10 に換算し（メンバー内の最大値を10とする）、体感負荷との差が4以上なら印を付ける。換算方法は余力マップの「？」マークに説明として表示する。
- **体感負荷アラート**：体感負荷が `high_load_score` 以上の回答が `high_load_consecutive` 回続いたら、実行委員長・副実行委員長（`role_assignments` から取得）に DM で知らせる。本人には「無理せず相談してください」という一文と、余力マップへのリンクを送る。

### 5.5 期限・停滞の判定ルール
- **期限切れ NA**：status ≠ 完了 かつ na_due < 今日（Asia/Tokyo）
- **今週期限**：status ≠ 完了 かつ 今日 ≤ na_due ≤ 今日+7日
- **停滞タスク**：status ≠ 完了 かつ updated_at が `stale_days` 日以上前
- **完了率**：完了件数 ／ アーカイブを除く全件数。0件なら「—」
- 日付・時刻はすべて Asia/Tokyo で扱う。

### 5.6 個人 DM リマインドのルール（F18）
毎朝の定時処理で、次の条件に当てはまる人に DM を送る。**1人あたり1日1通にまとめる**（項目ごとにメッセージを分けない）。

| 種類 | 条件 | 送り先 |
|---|---|---|
| 明日期限 | na_due = 明日 | 担当者 |
| 今日期限 | na_due = 今日 | 担当者 |
| 期限切れ | na_due < 今日（毎朝） | 担当者 |
| 期限切れ（責任者へ） | 超過が `overdue_escalation_days` 日以上 | そのタスクの各役職の責任者（担当者本人を除く）。1タスクにつき、責任者へは**最初の1回のみ** |
| 待ちの相手 | status=待ち かつ waiting_on_member_id がある（2日に1回） | 待たれている人 |
| 停滞 | 停滞タスク（週1回、月曜） | 担当者 |
| 依頼の返事待ち | 依頼中が `request_reminder_days` 日以上 | 担当者 |
| 新しい依頼・依頼への返事 | 前回の定時処理以降に発生 | 担当者／依頼した人 |
| 体感負荷の入力 | `checkin_weekdays` の曜日で、その日まだ回答していない | 全員 |
| 体感負荷アラート | 5.4 の条件 | 委員長・副委員長、本人 |

- DM の文面は、その人の `lang` に合わせる（日本語／英語）。
- 各項目にアプリの該当ページへのリンクを付ける。
- 送信内容は `reminder_log` に記録し、同じ内容を1日に2回送らない。
- `reminders_enabled=FALSE` の人には、体感負荷アラート以外の DM を送らない。
- `slack_user_id` が空の人は送信をスキップし、毎朝のまとめ投稿の末尾に「Slack ID 未設定：○名」とだけ出す（管理者が気づけるように）。

### 5.7 F14（議事メモ → NA）の詳細仕様
- Gemini に渡すもの：議事メモ本文（マスキング後）、会議日、役職一覧（role_id・名前）、メンバー一覧（member_id・表示名のみ。メールアドレスは渡さない）。
- 送信前に、メールアドレス・電話番号らしき文字列を `[メール]` `[電話番号]` に置き換える。画面にも「個人情報は貼り付けないでください」と表示する。
- 構造化出力（JSON スキーマ指定）で、候補ごとに `title` / `next_action` / `owner_member_id` / `role_ids` / `na_due` / `weight` / `evidence`（根拠となるメモの短い引用）を返させる。不明な項目は空。
- 返ってきた値は必ず検証する：存在しない ID は空にする、不正な日付は空にする、文字数の上限を超えたら切り詰める。
- 担当者・期限が空の候補は、画面で入力しないと登録できない。
- 1回に送れる議事メモは2万文字まで。
- API エラー時は「時間をおいて再試行してください」と表示し、入力したメモは画面に残す。

### 5.8 F20（ホーム検索バー AI 問い合わせ）の詳細仕様
- **画面仕様**:
  - ホーム画面の Search bar（56px、角丸 full）から送信すると、M3 Search view を展開。
  - 上部に「AI 回答カード（M3 Elevated Card）」、下部に「関連タスク一覧（M3 List）」を 2 層表示。
  - 回答生成中は、汎用キラキラアイコン（Material Symbols `auto_awesome`）とテキストシマー、スケルトンインジケーターを表示。
  - 回答文中の `[TASK:T-001]` 形式は、クリック可能な M3 Assist Chip に自動変換。存在しない `task_id` はサニタイズして非リンク化。
  - 免責事項「AI の回答です。正確な情報は各タスクをご確認ください」を常時表示。
  - キーワード検索との両立：単なるキーワード入力時も、下部に一致タスク一覧を提示し、「全タスク一覧で検索」へのショートカットを提供。
- **情報漏洩防止（コンテキストのホワイトリスト・ブラックリスト・S12）**:
  - **送信許可（Whitelist）**:
    - `tasks`: `task_id`, `title`, `phase/status`, `due_date`, `assignee`（displayName に置換して送信）, `role_names`, `weight`, `next_action`, `na_due`
    - `members`: `member_id`, `displayName`, `main_roles`（有効メンバーのみ）
    - `checkins`: 直近7日間の `member_id`, `date`, `score`, `auto_load`（数値のみ）
    - 質問者情報: `member_id`, `displayName`
  - **送信完全禁止（Blacklist）**:
    - `members.email`（メールアドレス）
    - `tasks.notes`（非公開メモ・自由記述）
    - `tasks.blocker`（ブロック要因の詳細）
    - `tasks.archived == TRUE`（アーカイブ済みタスク）
    - `checkins.comment`（体感負荷の自由記述コメント・愚痴）
    - `activity_log` / `reminder_log`
  - **PII マスキング**:
    - 質問文およびタスクタイトルに含まれうるメールアドレス（`[メール]`）および電話番号（`[電話番号]`）を正規表現で自動マスキングした上でプロンプトへ投入。
- **セキュリティ・プロンプトインジェクション防御**:
  - システムプロンプトで「指示無視命令の完全拒絶」「提供データ以外の推測回答禁止（不明時は『分かりません』と即答）」「読み取り専用（DB変更不可）」を明示。
  - Next.js Route Handler（`/api/ai-search`）によるサーバーサイド実行（Gemini API キーのブラウザ完全非露出）。
  - XSS 防止（S6）: 危険な `dangerouslySetInnerHTML` は使わず、自作の `SafeMarkdown` コンポーネントで仮想 DOM ノードとしてレンダリング。
- **レートリミット（S13）**:
  - 同一メンバーによる連続呼び出しを制限（既定: 1分あたり5回、1日あたり50回。`settings` シートで動的変更可能）。
- **機能フラグ**:
  - `settings` シートの `feature_ai_search`（初期値 `FALSE`）。FALSE の場合は AI 呼び出しを安全にスキップし、タスクのキーワード検索結果のみを表示。
- **ログ記録**:
  - `ai_queries` シートに `query_id`, `timestamp`, `member_id`, `query_text`, `grounded_task_ids`, `status`, `error_message` を記録。**個人情報保護のため、回答本文は一切保存しない**。

### 5.9 F21（Google Drive 資料連携・File Search）の詳細仕様
- **全体概要**:
  - Google Drive 内の専用フォルダ「AI共有」（`drive_ai_shared_folder_id`）に置かれた共有資料を、日次バッチ（`scripts/sync_drive_files.py`）で Gemini API のマネージド RAG「File Search Store」へ自動インデックス化。
  - F14（議事録 NA 抽出）および F20（ホーム AI 問い合わせ）において、タスクデータ（スプレッドシート）と共有資料（Drive）を横断して根拠を参照可能にする。
- **認証とキーレス同期**:
  - サービスアカウント（`task-app-run@...`）に Google Drive フォルダの「閲覧者（Viewer）」権限を付与（書き込み・削除権限は与えない）。
  - GitHub Actions からの自動実行には Google Cloud Workload Identity Federation (WIF) を利用し、秘密鍵 JSON を GitHub に置かないキーレス認証を標準とする。
- **ドキュメント変換と同期**:
  - Google ドキュメント・スライドは PDF に変換してエクスポートし、レイアウトとページ構造を忠実にインデックス化。
  - フォルダから削除または移動されたファイルは、File Search Store からも即座に抹消。
- **事前安全検査（ガードレール・S16）**:
  - ファイル取り込み前に本文を自動スキャンし、メールアドレス、電話番号、選考・健康・認証関連キーワード（選考結果、合格通知、面接評価、健康診断、病歴、暗証番号等）が検知された場合は、**File Search へのアップロードを直ちにブロック**。
  - `drive_sync_logs` に理由を記録し、管理者に警告通知を送る。
- **出典の明示と画面上の明確な区別（S18）**:
  - 回答内でタスクと資料の根拠を視覚的に明確に区別して表示：
    - タスク根拠: `[TASK:T-001]`（M3 Primary チップ / クリックでタスク詳細を開く）
    - 資料根拠: `[DOC:資料名|URL]`（M3 Document チップ / クリックで Google Drive プレビューを新規タブで開く）
- **プロンプトインジェクション対策（S17）**:
  - 資料内に書かれた命令文（「これまでの指示を無視して」等）を AI がプロンプトとして実行しないよう厳格なシステム命令を適用。

### 6.2 パフォーマンス・可用性
- Google Sheets の読み込みは `st.cache_data`（TTL 60秒程度）でキャッシュし、書き込み後はキャッシュを破棄する。
- Community Cloud は約12時間アクセスがないとスリープする。リマインド・まとめ投稿・集計は GitHub Actions で動くため、アプリがスリープしていても止まらない。
- 定時処理は毎朝1回・数分程度とし、GitHub Actions の無料枠（private リポジトリで月2,000分）に収める。
- 定時処理が失敗したら、GitHub のメール通知で管理者が気づけるようにする。途中で失敗して再実行しても、`reminder_log` と `daily_snapshots` の重複防止で二重送信・二重集計にならないこと。
- スプレッドシートのバージョン履歴をバックアップとして使う。加えて月1回、管理者がシートを複製して保管する。

### 6.3 UI/UX
- 日本語／英語。PC とスマートフォンの両方で使える（スマホでは1列表示）。
- Material Design 3（M3）準拠の視覚スタイルとモーション設計（詳細は `docs/ui_spec_m3.md` 参照）。
- **上部バーとプログレスインジケーターの役割分離**:
  - ヘルプボタンおよび単体の手動更新ボタン（⟳）は上部バーから削除（視覚ノイズの排除）。
  - **最上部 4px Linear Progress Indicator（ピンク）**: 画面ルーティング（ページ遷移）時のみ表示。
  - **アバター左 24px Circular Progress Indicator（不確定型）**: バックグラウンドでのデータ取得中・再検証中・保存中のみ表示（`role="progressbar"`、`aria-label="読み込み中"`）。非通信時は領域（24px）をキープしたまま不可視化し、レイアウトガタつきを防止。
  - **自動再検証ポリシー**: 別タブから戻った際（前回取得から60秒以上経過時）に自動再取得、および開いたままの画面で5分ごとの定期更新。
  - **手動更新**: 強制的に更新したいユーザーのため、アバターメニュー内に「最新データに更新」を配置。
- **Google Workspace 風 AI 生成中アニメーション（NA 生成・議事録）**:
  - 生成中は、議事メモカードの枠線に青・紫・ピンク系（`#0B57D0`, `#6B4FBB`, `#9C2A5C`）のグラデーション光がゆっくり流れる。
  - 「NA の候補を作成しています」テキストにシマー（左から右へ流れる光）。
  - 結果表示エリアに 3 行のスケルトンカード（グラデーションシマー波）を表示。
  - 結果到着時、上から順に 80ms 刻みで段階的にふわっと表示（スタッガードアニメーション）。
  - 商標保護：Google/Gemini のロゴや商標は使用せず、Material Symbols `auto_awesome`（キラキラ）を使用。
  - `prefers-reduced-motion: reduce` が有効な場合は、すべての回転・シマー・スタッガードを停止し、静止表示に切り替える。
- ステータスの色：未着手＝グレー、進行中＝青、待ち＝黄、完了＝緑。期限切れは赤（淡い error-container 背景と控えめな文字）。
- 主要操作（NA の更新、体感負荷の回答、依頼の承諾）は **2クリック以内**。
- 体感負荷の色：1〜4＝緑、5〜7＝黄、8〜10＝赤。色だけに頼らず数値も表示する。
- 負荷に関する画面では、責める表現（「遅れ」「少ない」など）を避け、中立的な表現（「期限を過ぎた NA」「余裕がある」など）を使う。
- エラー時は、何をすればよいかを表示する。

### 6.4 保守性・引き継ぎ
- `README.md` にセットアップ・デプロイ・シート構成・定時処理・各 API キーの管理方法・`settings` の各項目の意味を記載する。
- 主要な関数には日本語の docstring を付ける。
- `core/` のロジックは `pytest` でテストする。外部サービスはダミー実装でテストする。

## 7. 運用ルール（アプリの外で決めること）

- **体感負荷は評価に使わない。** 分担を話し合うための材料として使う。アプリ導入時に実行委員会で合意する。
- 体感負荷は週3回（月・水・金）に回答する。状況が大きく変わったら、曜日に関係なくいつでも更新してよい。
- 定例会の冒頭で、F5（期限アラート）と F15（余力マップ）を画面共有して確認する。
- タスクを他の人に振るときは、アプリで「依頼」する。口頭で頼んだ場合も、後でアプリに登録する。

## 11. 既存本番スプレッドシートへの手動追加手順（ai_queries シート）

既存の本番スプレッドシートの既存データを保持したまま、新機能 F20（AI 問い合わせ）およびログ記録に対応させるための手順です。

### 手順 1: `ai_queries` シートの追加
1. Google スプレッドシートを開き、左下の「**＋**（シートを追加）」をクリックします。
2. シート名を `ai_queries` に変更します。
3. 1行目（A1:G1）に、以下のヘッダーを半角英字のまま正確に入力します（コピー＆ペースト推奨）：

| A1 | B1 | C1 | D1 | E1 | F1 | G1 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| `query_id` | `timestamp` | `member_id` | `query_text` | `grounded_task_ids` | `status` | `error_message` |

### 手順 2: `drive_sync_logs` シートの追加（F21 Drive資料連携用）
1. 左下の「**＋**（シートを追加）」をクリックします。
2. シート名を `drive_sync_logs` に変更します。
3. 1行目（A1:I1）に、以下のヘッダーを正確に入力します：

| A1 | B1 | C1 | D1 | E1 | F1 | G1 | H1 | I1 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| `file_id` | `file_name` | `mime_type` | `drive_modified_time` | `gemini_file_resource_name` | `status` | `drive_link` | `last_synced_at` | `error_message` |

### 手順 3: `settings` シートへの設定行追加
`settings` シートの末尾行に、以下の各行を追加します：

| key (A列) | value (B列) | 説明 |
|---|---|---|
| `feature_ai_search` | `FALSE` | AI 検索機能を有効化する場合は `TRUE` に変更（課金設定完了後に有効化） |
| `rate_limit_ai_search_per_minute` | `5` | 1分あたりの呼び出し上限回数 |
| `rate_limit_ai_search_per_day` | `50` | 1日あたりの呼び出し上限回数 |
| `drive_ai_shared_folder_id` | （空） | Google Drive の「AI共有」フォルダID（フォルダURLの末尾文字列） |
| `gemini_file_search_store_name` | （空） | Gemini File Search Store リソース名（自動生成または指定） |
| `feature_drive_file_search` | `FALSE` | Google Drive 資料連携を有効化する場合は `TRUE` に変更 |
