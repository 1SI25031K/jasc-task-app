# AI エージェント向け 共通ルール

このプロジェクトで作業する AI エージェントは、毎回このルールに従うこと。

## 前提
- 開発者（私）はプログラミング学習中。**学習が目的の一つ**なので、速さより「理解できること」を優先する。
- 仕様は `docs/requirements.md` が正。迷ったらそれに従い、書かれていないことは勝手に決めずに質問する。

## 進め方
1. 作業前に必ず **実装計画（Implementation Plan）** を出し、私の承認を待ってからコードを書く。
2. 1回の作業は、指示されたフェーズの範囲だけにする。先のフェーズの機能を先回りして作らない。
3. 作業が終わったら、次を報告する：
   - 作った・変えたファイルの一覧と、それぞれの役割（1〜2行）
   - 私が手で確認すべきこと（動作確認の手順）
   - 次のフェーズに進む前に私がやる必要がある作業（あれば）
4. フェーズごとに `docs/learning/phaseN.md` を作り、初心者向けに以下を書く：
   - このフェーズで使った技術・概念の説明（なぜそれを使うのか）
   - 重要なコード3か所程度の読み方の解説
   - 理解度チェックの質問を3つ（答え付き、折りたたみ形式）

## コーディング規約
- Python 3.12、型ヒントを付ける。
- 関数・クラスには日本語の docstring を付ける。
- 画面（`pages/`）にロジックを書かない。ロジックは `core/services.py` に置き、テストを書く。
- 外部サービス（Google Sheets）へのアクセスは `Repository` 経由のみ。
- 日付・時刻は `zoneinfo.ZoneInfo("Asia/Tokyo")` で扱う。
- 画面の文言は直書きせず、必ず `locales/ja.toml` / `locales/en.toml` に追加して `core/i18n.py` 経由で表示する。日本語と英語の両方を同時に追加する。
- Slack・Gemini などの外部サービスは、インターフェース（`Notifier` / `NaExtractor`）経由で使う。テストではダミー実装を使い、実際に通信しない。
- Gemini のモデル名は設定（secrets）から読む。コードに直書きしない。

## セキュリティ（絶対に守ること）
- 秘密情報（API キー、クライアントシークレット、サービスアカウント鍵、cookie_secret）をコード・コミット・ログ・チャットに出力しない。`.streamlit/secrets.toml` は Git 管理外。
- 実在の個人名・メールアドレス・電話番号をコードやテストデータに書かない。ダミー（例：`メンバーA` / `member_a@example.com`）を使う。
- ユーザー入力を `unsafe_allow_html=True` で表示しない。
- UI 装飾における静的 CSS / HTML の限定利用：M3 の Progress / Loading indicator や Google ログインボタン等、Streamlit 標準機能で表現できない静的装飾に限り、`core/ui/` 配下の独立モジュールに静的 CSS / SVG を集約して使用することを許可する。ただし、ユーザー入力や AI 出力の文字列を CSS / HTML 内に埋め込むこと（文字列補間）は一切禁止する（S6）。ユーザー入力・AI 出力を表示する箇所は、必ず Streamlit 標準の安全なウィジェット（`st.markdown`, `st.text_input` 等）を使用する。
- スプレッドシートへの書き込みは `value_input_option="RAW"`。
- 破壊的なコマンド（ファイルの一括削除、`git push --force`、`git reset --hard` 等）は実行前に必ず私に確認する。
- 新しいパッケージを追加するときは、名前と理由を先に説明して承認を得る。

## 動作確認
- 画面を変更したら、内蔵ブラウザでローカル起動したアプリを開き、スクリーンショットで確認してから報告する。
- `pytest` が全件通ることを確認してから報告する。
