## 1. このフェーズで使った技術・概念の説明（なぜそれを使うのか）

### ① `uv`（ユーブイ）と `pyproject.toml`
- **何か**：Python のバージョン管理と、外部ライブラリ（部品）のインストールをまとめて高速に行ってくれる最新のパッケージ管理ツールです。
- **なぜ使うのか**：
  Python で開発するとき、パソコン本体にそのままライブラリを入れてしまうと、別のプロジェクトを作るときにバージョンの衝突が起きて動かなくなることがあります。
  `uv` を使うと、このプロジェクト専用の隔離された部屋（`.venv` という**仮想環境**）を自動で作ってくれます。また、使ったライブラリの種類を `pyproject.toml` に、正確なバージョン番号を `uv.lock` に記録してくれるため、他のメンバーのパソコンや本番サーバー（Streamlit Community Cloud）でも**まったく同じ環境**を再現できます。

### ② Streamlit（ストリームリット）
- **何か**：Python のコードだけで Web アプリの画面（UI）を作れるフレームワークです。
- **なぜ使うのか**：
  通常、Web アプリを作るには HTML・CSS・JavaScript といった画面用の言語と、Python などの裏側用の言語の両方を書く必要があります。Streamlit を使えば、Python で `st.title("...")` と1行書くだけで見出しが表示されるため、シンプルで壊れにくく、来年度の実行委員にも引き継ぎやすいアプリが作れます。

### ③ `pytest`（パイテスト）
- **何か**：書いたプログラムが意図通りに動くかを自動でチェック（テスト）してくれるツールです。
- **なぜ使うのか**：
  アプリが大きくなると、「新しい機能を追加したら、前に作った機能が壊れていた」ということがよく起きます。`pytest` でテストコードを書いておけば、コマンド1つで何十個ものチェックを一瞬で実行でき、安心してコードを書き換えられるようになります。

### ④ Git（ギット）と `.gitignore`（ギットイグノア）
- **何か**：
  - **Git**：ファイルの変更履歴を記録する「タイムマシン（セーブポイント）」のような仕組みです。
  - **`.gitignore`**：Git に「このファイルやフォルダは記録しないで（無視して）ね」と伝える設定ファイルです。
- **なぜ使うのか**：
  パスワードや API キーを書いたファイル（`.streamlit/secrets.toml`）を誤って GitHub にアップロードしてしまうと、重大なセキュリティ事故になります。また、`.venv/` のような巨大なフォルダ（数千ファイル）を Git に入れると動作が重くなります。そのため、最初に `.gitignore` を作ってこれらを除外するのが鉄則です。

## 2. 重要なコード3か所の読み方の解説

### ① `app.py`（アプリの入り口）

```python
import streamlit as st


def main() -> None:
    """アプリのメイン画面を表示する。"""
    st.title("JASC タスクマネージャー（準備中）")


if __name__ == "__main__":
    main()
```

- `import streamlit as st`：Streamlit というライブラリを読み込み、これ以降 `st` という短い名前で使えるようにしています。
- `def main() -> None:`：`main` という名前の関数（処理のまとまり）を定義しています。`-> None` は「この関数は計算結果の値（戻り値）を返さず、画面表示だけを行う」という**型ヒント**です。
- `"""アプリのメイン画面を表示する。"""`：関数のすぐ下に書く説明文を **docstring（ドックストリング）** と呼びます。後から自分や他の人が読んだときに、何をする関数かすぐわかるように書きます。
- `st.title(...)`：画面に大きな見出し（タイトル）を表示する Streamlit の命令です。
- `if __name__ == "__main__":`：「このファイルが直接実行されたときに、`main()` 関数を動かす」という Python の定番の書き方です。

### ② `pyproject.toml`（プロジェクトの設計図）

```toml
[project]
name = "jasc-task-app"
version = "0.1.0"
description = "Add your description here"
requires-python = ">=3.12"
dependencies = [
    "pytest>=9.2.0",
    "streamlit>=1.66.1",
]
```

- `requires-python = ">=3.12"`：このアプリを動かすには Python 3.12 以上が必要であることを宣言しています。
- `dependencies = [...]`：このアプリが依存している（必要としている）外部ライブラリの一覧です。`uv add streamlit pytest` を実行したときに、自動でここに追加されました。

---

### ③ `.gitignore`（Git から除外するリスト）

```gitignore
# Python / 仮想環境
.venv/
__pycache__/

# Streamlit の秘密情報（絶対にコミットしない）
.streamlit/secrets.toml
```

- `#` から始まる行はコメント（メモ書き）です。
- `.venv/`：先頭にドット `.` がつくフォルダやファイルは、Mac では「隠しフォルダ・隠しファイル」として扱われます。ここにはインストールされたライブラリの本体が入っています。
- `__pycache__/`：Python がプログラムを速く動かすために自動で作る一時フォルダです。パソコンごとに自動生成されるため、Git には入れません。
- `.streamlit/secrets.toml`：今後 Google ログインや Slack・Gemini の鍵を書くファイルです。**絶対に Git に入れない**よう、ここでブロックしています。

## 3. 理解度チェック（3問）

### Q1. なぜ `.streamlit/secrets.toml` を `.gitignore` に書く必要があるのでしょうか？
<details>
<summary>答えを見る</summary>

**答え**：`secrets.toml` には API キーやパスワードなどの**秘密情報**を書くため、Git に記録して GitHub にアップロードしてしまうと、外部や他の人に秘密情報が漏洩してしまうからです。`.gitignore` に書いておくことで、うっかりコミットしてしまう事故を防げます。
</details>

---

### Q2. `app.py` の `def main() -> None:` にある `-> None` は何を表していますか？
<details>
<summary>答えを見る</summary>

**答え**：**型ヒント（Type Hint）** と呼ばれるもので、「この `main` 関数は、処理が終わったあとに何も値を返さない（`return` しない）」ということを人間やエディタにわかりやすく伝えています。
</details>

---

### Q3. 他のメンバーが GitHub からこのプロジェクトをダウンロードしたとき、なぜあなたのパソコンと同じバージョンの Python や Streamlit を使えるのでしょうか？
<details>
<summary>答えを見る</summary>

**答え**：`pyproject.toml`（必要なPythonやライブラリの宣言）と `uv.lock`（実際にインストールされた全ライブラリの正確なバージョン一覧）が Git で共有されているからです。他のメンバーが `uv sync` や `uv run` を実行すると、`uv` がこれらのファイルを読んで同じ環境を `.venv` に自動で作ってくれます。
</details>
